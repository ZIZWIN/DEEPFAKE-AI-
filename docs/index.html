How it Works

01

Upload

User submits an image file via the React frontend. It's routed to the FastAPI backend without compression.

02

Analyzers Run

The Pipeline orchestrator runs all 7 forensic analyzers concurrently, extracting local and global signals.

03

Scores Weighted

Individual analyzer scores (0.0 to 1.0) are multiplied by their confidence weights to compute an overall risk score.

04

JSON Report

A comprehensive report with raw scores, individual findings, and the final verdict is returned to the dashboard.

Scoring & Verdicts

The system aggregates findings into a single risk score between 0.0 and 1.0, categorized into three tiers.

< 0.3

Authentic

No significant indicators of manipulation detected. Signals remain consistent with straight-out-of-camera (SOOC) images.

0.3 – 0.6

Suspicious

Some anomalies found. Could indicate heavy harmless editing (e.g., Photoshop, filters) or minor localized manipulation.

≥ 0.6

Likely Manipulated

Strong, overlapping indicators of manipulation. High probability of AI generation, deepfaking, or extreme structural editing.

The 7 Forensic Analyzers

📝

EXIF Metadata

metadata.py

What it checks: Presence of camera maker notes, software signatures, missing timestamps, and GPS logic.

Why it works: Generative AI models rarely write coherent, hardware-level EXIF structures. Stripped metadata elevates the baseline risk score.

🔍

Error Level Analysis (ELA)

error_level.py

What it checks: The difference in pixel values after artificially re-saving the image at a known JPEG quality (e.g., 90%).

Why it works: Inserted elements (splicing) or GAN-generated faces sit at a different compression potential than the surrounding authentic background.

🌫️

Noise Pattern

noise.py

What it checks: Uniformity of high-frequency noise variance across different spatial blocks of the image.

Why it works: Authentic camera sensors produce uniform noise. AI generators and composites produce smooth regions lacking natural sensor grain.

🌊

Frequency Domain (FFT)

frequency.py

What it checks: The Fast Fourier Transform (FFT) spectrum for unnatural repeating grids or sudden drop-offs in high frequencies.

Why it works: Up-convolution layers in GANs/Diffusion models often leave imperceptible periodic grid artifacts in the frequency domain.

📦

JPEG Compression (DCT)

compression.py

What it checks: Discrete Cosine Transform (DCT) coefficients, quantization tables, and 8x8 block boundary alignment.

Why it works: Repeatedly editing or pasting a JPEG shifts the 8x8 block alignment, leaving double-quantization traces invisible to the naked eye.

🎨

Color Consistency

color.py

What it checks: RGB channel correlation, hue/saturation entropy, and lighting direction variance.

Why it works: Deepfakes often struggle with consistent illumination angles and cross-channel color bleeding, creating statistical anomalies.

🛡️

SynthID Watermark

synthid.py

What it checks: Spatial Least Significant Bit (LSB) anomalies and known frequency modulation signatures injected by Google's Imagen.

Why it works: Identifies invisible, imperceptible robust watermarks specifically designed to flag AI-generated content.

Architecture

Backend (Python / FastAPI)

  • Exposes the /api/v1/analyze REST endpoint.
  • Accepts multipart/form-data file uploads.
  • Orchestrates the AnalyzerPipeline which manages parallel execution of forensic modules.
  • Calculates the weighted average based on module confidence.
  • Returns a heavily structured JSON response detailing findings per module.

Frontend (React / Vite / TS)

  • Single Page Application styled with TailwindCSS.
  • Handles drag-and-drop file ingestion via ImageUpload.tsx.
  • Renders the dynamic ScoreGauge.tsx based on the API response.
  • Maps individual analyzer findings into expandable cards in ResultsPanel.tsx.

Extending the System

Adding a new forensic analyzer is simple. Inherit from BaseAnalyzer, implement the analyze method returning an AnalyzerResult, and register it in pipeline.py.

from app.analyzers.base import BaseAnalyzer, AnalyzerResult
from PIL import Image

class MyCustomAnalyzer(BaseAnalyzer):
    def __init__(self):
        super().__init__(
            name="Custom Forensic Check",
            weight=1.0 # Confidence weighting in final score
        )

    def analyze(self, image: Image.Image) -> AnalyzerResult:
        # Perform custom mathematical analysis here
        score = self._calculate_anomaly(image)
        
        return AnalyzerResult(
            analyzer_name=self.name,
            score=score,
            verdict="suspicious" if score > 0.5 else "authentic",
            findings=[{"metric": "Custom variance", "value": score}]
        )

Limitations & Known Issues

⚠️

Full-Image Analysis Only

Currently, the system analyzes the entire image frame. It lacks facial extraction (MTCNN/RetinaFace), meaning small deepfaked faces in a large authentic background may be diluted.

⚠️

JPEG Dependency

Many analyzers (ELA, DCT Compression) rely heavily on JPEG artifacts. Analyzing PNGs or heavily compressed web-formats (WebP) significantly lowers their confidence weighting.

⚠️

Social Media Stripping

Social media platforms (WhatsApp, Twitter, Instagram) strip EXIF metadata and recompress images. This can trigger false "Suspicious" flags on authentic images.

⚠️

Harmless Editing False Positives

Because the system relies on mathematical anomalies, heavily edited real photos (e.g., Lightroom color grading, Photoshop spot healing) may flag as Likely Manipulated.

Frequently Asked Questions

Can it detect video deepfakes? +
The frontend supports video uploads and the backend processes videos frame-by-frame. However, temporal artifacts (unnatural flickering, motion inconsistency) are not yet integrated into the heuristic scoring pipeline — only spatial signal extraction is performed per frame.
Why does my real photo show as suspicious? +
Heuristic analyzers flag structural changes, not intent. If your photo was resized, sent via WhatsApp, edited in Lightroom, or run through any social media compression pipeline, the mathematical structure has been altered — which produces the same red flags as AI manipulation. This is a known limitation.
What image formats are supported? +
The most accurate results come from original JPEG files. PNG is supported but has no DCT coefficients, so the JPEG compression analyzer is skipped. WebP is supported but format conversion strips valuable quantization data, reducing the reliability of several modules.
How accurate is the detector? +
Because this system uses signal extraction rather than ML classification, it doesn't have a single "accuracy" metric. It computes a mathematical probability of structural integrity. In testing on clearly AI-generated images, it achieves >85% true positive detection, with a higher false-positive rate (~15–20%) on heavily edited real photographs.
Can I add my own analyzer? +
Yes — the backend uses a fully modular pipeline. Subclass BaseAnalyzer, implement analyze(image) → AnalyzerResult, and register your class in pipeline.py. It will automatically appear in the API response and UI results panel. See the Extending section above for a code example.
Does it store my uploaded images? +
No. Files are received by FastAPI, decoded into an in-memory PIL Image object for the duration of the analysis, and then immediately garbage-collected. No images, metadata, or analysis results are persisted to disk or any database.
